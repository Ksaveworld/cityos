# 调度台改造意图

这份文档回答「为什么要改、改成什么样算成功」。**不谈怎么做。**

怎么做分两份：`地图要素显示规则.md` 管显示口径，`调度台改造路线图.md` 管推进顺序。
三份合起来是一条链：意图 → 规格 → 计划。

---

## 现在的问题

调度台是一个**表单**。

三个竖排单选列表（选中队、选接收点、选处置档位），点「应用调整并重算」，
右侧两个数字跳一下。游戏里对应的东西是设置菜单，不是指挥台。

具体三条：

**一、选择这件事不产生空间信息。**

资源调度本质是空间问题——谁离得近、走哪条路、走了之后哪块没人管。但当前
呈现把它压成了列表选择。列表在大屏上永远不好看，因为它跟地图抢注意力却不
产出空间价值。

参赛版 `cityos` 里更彻底：调度面板整个文件搜不到一处地图引用，面板和地图
只是上下摆着，没有数据往来。正式版已用 `CommandTacticalMap` 与拖拽交互
解决了这一条。

**二、代价说不出来。**

抽调一支力量的后果，现在是一个词：覆盖风险「较低 / 注意 / 较高」。

这是整套系统最该被看见的东西，却用三个形容词打发了。

**三、到场时间是查表加减法。**

预置常数相加，不是求解出来的。而 `src/engine/routing/` 里有一个能在真实
路网上跑的求解器，调度层一次都没调用过。

后果是：选一个肉眼看着明显更远的站，时间只涨零点几分钟。**视觉做得越好，
这个破绽越明显。**

## 目标

**让人相信这个系统真的能用。**

这是在两个可能目标里的一次明确取舍：

| 目标 | 代价 |
|---|---|
| 让人相信这**思路**是对的 | 容易。可以大方标注模拟，力气全花在把推演讲清楚 |
| 让人相信这**系统**真能用 | 难。必须有真东西撑着，任何假装真的地方都是风险 |

**选后者。** 因为真东西已经有了，只是被埋掉了：底图、路网、建筑轮廓、设施
位置都是实测数据，路径求解是真跑的。假的只有一样——车辆此刻在哪。

---

## 成功标准

1. **三米外能看清。** 展台上人是站着看的。现存界面大量 8px / 9px 文字在
   投屏上等同不存在。
2. **随便点不翻车。** 没有「正确的操作顺序」。任何要素、任何时候被点或悬停，
   都要有反应。
3. **真的那部分要被看见。** 尤其是路径——它必须弯弯绕绕贴着真实街道走。
   直线一眼假，复杂形状一眼真，这是「算出来的」唯一能被肉眼看见的地方。

## 已经做出的判断

这些是过程中定下、且推翻代价较高的决定，记在这里避免以后重新争论。

**一、不逐条标注「模拟」，改为分层一次说清。**

满屏免责声明会把真本事一起埋掉，也直接和上面的目标冲突。做法是进入页
一屏交代哪层实测哪层模拟，界面内只在车辆实时状态这一类保留轻标记。

这不是弱化「真实与诚信」，是让它生效——观众能分清哪些是真本事，
比看见一堆「模拟」有说服力得多。详细口径见 `数据边界.md`。

**二、不做赛博朋克风格的图标。**

霓虹描边、故障效果、括号包边第一眼很爽，但会被立刻读成「游戏 / 概念 demo」，
与本文档的目标直接冲突。

气质放在**光**上——深色底、路径发光、辉光呼吸；图标本身保持专业冷静。
结果应当是「一台很酷的真设备」，不是「一个很酷的游戏」。

**三、图标形象不推翻。**

8/20 评审当面点了「高德元素」这类一眼能认出的形象标识，8/21 评审又调过
火情与消防站的字形区分。真正的问题不在图标，在 19 种要素配了 19 个颜色。

**四、调度台与演示是两条线，调度台先做。**

演示线是「自动点调度台按钮的幽灵操作员」，不是另一套界面。如果演示单独
做一层壳，观众看完很爽、一上手发现点不动，信任当场崩——比不做演示更糟。

**五、按刀切，不按层做。**

最大风险不在任何一层，而在「覆盖圈收缩那半秒到底有没有力量」这个未验证的
假设。所以先用全假数据把那一下做出来，不行就立刻停。

## 边界

以下不在本次范围内，且任何时候出现都是走错方向：

- **不做火情检测、不建感知网络。** 事件从既有系统接入，我们只做事件已知
  之后的部分。见 `CLAUDE.md`。
- **不做三维建模。** 视觉方案是城市尺度 2.5D 挤出加建筑尺度 SVG 剖面，
  不引入 Cesium / Three.js / 三维模型资产。
- **不预测事故发生。** 只计算既定选项的后果。对外口径必须守住这条。
