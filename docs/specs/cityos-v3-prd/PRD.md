## 1. 一句话

**城市里发生了事，CityOS 在几分钟内给出两三个可执行的方案，说清每个方案的后果，人挑一个批准，系统把任务派到具体负责人手上。**

不做火情识别，不建摄像头网络。事情是从 119、110、物业、传感器这些**已有系统**报进来的，我们做的是**事情已知之后**的部分。

---

## 2. 这东西是演给谁看的

比赛评委。周二（8/25）。

评委看完要留下三个印象：

1. **这是个真能用的系统**，不是四个写死的案例在轮播
2. **它的画面配得上"城市指挥中枢"这几个字**——对标组已经把视觉标准拉高了
3. **它诚实**——哪些数据是真的、哪些是模拟的，界面上分得清

第 3 条不是道德要求，是评分维度（"真实与诚信"）。

## 3. 现在这版为什么要推倒重来

不是代码烂，是**产品结构和视觉方向都错了**。原话摘录：

### 3.1 四个功能模块高度重合

> 「态势总览、事件处置、资源调度、复盘评估……这 4 个功能模块儿不是很清晰。这 4 个功能点需要你们再捋一下，或者做什么功能点都可以。反正这 4 个功能点现在看下来就高度重合，高度重合不太行。」

根因：四个 tab 点进去看到的是**同一张地图、同一套事件**，只是换了个侧栏。它们没有各自的主角。

### 3.2 报告的理解完全错了

> 「大康说他做的那个报告吧，那不叫报告，形式也好、层次也好，都不对。他的那个报告是所有事件完事儿之后生成一个复盘报告，不对。」
>
> 「报告应该是基于现在已有的数据流信息流，同步生产出来一个可以执行的方案。**那个方案就是报告**，那玩意儿得足够细化。这是一份儿报告，另一份儿报告是复盘的那个报告，那个也需要细化。」

这是最要命的一条。**方案本身就是报告，是产品的主交付物**，不是流程走完之后附赠的总结。

### 3.3 AI Brief 太薄

> 「AI brief 那一块儿，就是基于那些信息去生产报告，那些信息也不够全面，信息量太少了。」

报告是从 Brief 长出来的。Brief 薄，报告就厚不起来。

### 3.4 四个案例不该当导航

> 「如果系统投入正式使用怎么可能放四个雷霆例子，这几个只做为模拟数据来触发策略展示。」

现在把「荔湾火情 / 刑民警情 / 交通协同 / 重大布防」四个具体案例摆在地图顶上当一级 tab。真实系统不会这么干——那是四条**模拟数据**，用来触发方案演示，不是导航结构。

### 3.5 缺主看板，且视觉方向错了

> 「主界面缺少 dashboard。」
> 「资源调度模块的意义是什么？没看见调度。」

以及视觉。**问题不在颜色，在密度和克制。** 对标组那版可取的是**布局**：地图铺满整屏、数据卡浮在地图上层、右侧滚动告警流、大字号 KPI。

**颜色照高德走浅色**，见 `视觉规格.md`。曾一度把对标组的深色一并抄过来，那是错误推广——用户给那张截图是为了说明布局密度，不是要整个产品变深，而且用户明确要的是"高德那种感觉"，高德本身就是浅色。

### 3.6 图层的产品语言不对

> 「天气状况直接改整个界面配色，下雨就雨特效；上游视频的节点大小缩小；道路状况参考地图 app 的视觉语言。」
> 「你的那个道路情况图层，点进去就是一个绿色的道，原本的加粗了、加深了，这不对。」

## 4. 产品结构：四个模块重新捋

### 4.1 划分原则

四个模块之所以重合，是因为**主角是同一个**。要不重合，每个模块得有自己的主角：

| 模块 | 主角 | 一句话 |
|---|---|---|
| **态势总览** | 城市 | 整座城现在什么状况 |
| **事件处置** | 一个事件 | 这一件事怎么办 |
| **资源调度** | 人和车 | 手上有什么，现在派谁去 |
| **知识库** | 沉淀下来的推演 | 以前遇到过什么，当时怎么判的 |

城市 / 事件 / 资源 / 知识。四个主角完全不同，就不会重合了。

### 4.2 态势总览（Dashboard）

**主角是城市，永远不进入单个事件的处置流程。**

- 地图铺满整个视口，数据卡**浮在地图上层**，不是并排三栏挤压地图。底色浅，见 `视觉规格.md`
- 左侧：实时 KPI（今日事件、待决策、执行异常、在途单位、路网拥堵、能见度）+ 趋势曲线
- 右侧：**滚动的告警流**——最新告警一条条往下滚，带时间、来源、严重度
- 顶部：五个业务域（119 / 110 / 120 / 交通 / 重大布防）**同级并排**，每个带当前起数
- **默认就有异常。** 城市安全不存在"一切正常"的空态

点告警流里的任意一条 → 跳进「事件处置」。这是两个模块唯一的连接点。

### 4.3 事件处置

**主角是一个事件。**

事件从三个地方来，但进来之后走的是**同一条链路**：

1. **自动弹入**——打开系统就有事件在那儿，演示"系统在实时监控这座城"
2. **手工输入**——当场填表单，演示"你给我数据我就能推演"
3. **历史案例**——荔湾 5·16、广州火车站持刀伤人这些，作为一种事件来源埋在这里

> 荆渤韬原话：「4 个历史 case 展示，也不一定非要做成一个模块儿，专门放 4 个历史 case 的展示，完全可以就是埋在日常里边儿。」

链路（**这条是对的，不用改**）：

```
事件进来
  → 系统补齐（地址标准化、关联建筑、查周边资源、关联道路天气）
  → AI Brief 态势快照
  → 生成 2 个候选方案
  → 【方案报告】← 这就是主交付物，见第 5 节
  → 人工批准
  → 负责人任务包 + 送达状态
  → 执行反馈
  → 【复盘报告】← 第二份报告
```

历史案例比日常多一段：**街区级动态执行演示**（车辆沿路线跑、路口开路、时间线推进），以及**新旧方案对比**。

### 4.4 资源调度

**主角是人和车，不是事件。**

> 荆渤韬原话：「我主动的调控人力，或者说在事情发生之后，我在这个面板上可以主动调控人力。」

这个模块回答的是：**方案给出来了，但我觉得资源配得不对，我要手动改。**

具体长这样：

- 列出当前所有在途和待命的单位：消防中队、救护车、巡逻警力、清障车
- 每个单位显示：在哪、状态（待命/在途/现场）、被哪个事件占用
- **可以手动改**：某中队抽 2 车去支援另一起、某医院接收能力不够改派别家
- 改完立刻：**重算 ETA 和覆盖风险 → 原来的批准作废 → 必须重新人工批准**

这才叫"调度"。现在那版只是把资源列出来看，所以荆渤韬说"没看见调度"。

**最小闭环只演示一条**：改车辆数量 / 资源点 / 负责人 → 重算 → 旧批准失效 → 重新批准 → 允许一次重试。第二次重试禁用。

### 4.5 知识库

**主角是沉淀下来的推演。**

> 荆渤韬原话：「复盘评估这块儿做最好做成智库的形式，不要中间一个雷霆地图做展示，这产品语义语言都不对。」

所以：**这个模块里没有地图。**

- 列表 + 检索。每条是一次完整推演的沉淀
- 每条包含：案例标题、事件事实、当时的未知项、选定方案摘要、数据来源、生成时间
- 点进去是**复盘报告**（第 5.2 节）
- 对外口径：每次推演沉淀的数据保留在知识库，用于模型参数校准

**名字不叫"复盘评估"也不叫"案例库"**，具体叫什么待定。

## 5. 两份报告（本次重构的核心）

### 5.1 方案报告 — 主交付物

**什么时候生成**：事件处置过程中，方案生成的同时就出来，**不是等流程走完**。

**基于什么**：当前已有的数据流和信息流（Signal、事件事实、补齐的上下文、AI Brief）。

**它是什么**：一份**可以直接拿去执行**的东西。批准之后发给负责人的就是它。

**必须包含**（结构参考《City OS 修改方案》里那张配图）：

1. **执行摘要**——三五行说清要干什么
2. **事件事实与方案效果**——已确认的事实，以及这个方案预计带来什么
3. **方案原则与适用条件**——什么前提下这个方案成立，前提不成立时降级到哪
4. **人员编组与资源部署**——具体到「5 个单位、42 人、7 辆车」这种颗粒度
5. **路线、关键路口与时间窗**——地图标注，哪个路口几点几分开路
6. **各部门任务清单**——消防干什么、公安干什么、医疗干什么、交管干什么，按顺序
7. **联络方式**——每个任务对应的负责人和联系方式
8. **风险、缺口与备选措施**
9. **数据来源及真假说明**
10. **最终确认**——人工签字栏

**关键**：至少生成 2 个方案，就有 2 份这样的报告，摆在一起让人选。不是"生成一个方案 + 附一份报告"。

**够不够细的判断标准**：把这份报告打印出来交给一个消防中队长，对方不用再问任何问题就能出车。达不到这个标准就是不够细。

### 5.2 复盘报告 — 第二份

**什么时候生成**：事件处置完成之后，或者历史案例的动态演示结束之后。

**必须包含**（参考 wiki 里那张复盘对比配图）：

1. **两条时间线并排**——历史真实处置时间线 vs CityOS 模拟方案时间线
2. **核心数据对比**——关键节点数量、任务总数、资源调度耗时
3. **路线规划对比**
4. **时间与资源成本对比**
5. **规避的受阻点**
6. **未解决的风险**
7. **数据与推演边界**

**口径红线**：只能说"在同一套假设下，两个方案的差异是什么"，**不能说"证明 CityOS 更优"、"历史还原完成"**。

> 注意：wiki 里那张配图的文案写的是「CityOS 方案在缩短处置时间、减少资源成本、规避受阻点等方面的优势」。这句话跟上面的红线冲突。**这个要跟王君梅当面确认按哪个口径。**

### 5.3 AI Brief 要加厚

报告是从 Brief 长出来的。Brief 现在太薄，报告就细化不了。

Brief 固定四块，**每块至少 3 条、建议 5 条**：

1. **已确认事实**——时间、地点、事件类型和等级、关键人员或建筑信息
2. **待确认信息**——有哪些还不知道、谁去核实、走什么渠道
3. **系统补齐的上下文**——建筑参数、周边资源、道路状况、天气
4. **信息缺口与影响**——缺什么、当前按什么假设在跑、这个假设影响哪个方案、什么情况下要重新研判

每条都要标：**来源**、**确认状态**、**真/模拟/估算/未知**。

**页面怎么设计还没定**——王君梅那边没出稿。先按四块卡片做，别在这上面投太多时间。

## 6. 视觉方向

> **本节已被 `视觉规格.md` 取代。** 那份是唯一视觉权威，色值从高德地图瓦片逐像素实测得出。
>
> 2026-08-20 深夜推翻两条：
>
> 1. **推翻「深色大屏」。** 全产品浅色，一套色板，没有第二套主题。深色是错误推广——用户给的那张吉隆坡截图是对标组的 dashboard 参考，不是要我们整个产品变深。
> 2. **推翻「路况铺满全图」。** 高德默认地图根本不显示路况，实测四张瓦片零个彩色路段。路况是可开关的叠加层，且只叠主干道。
>
> 保留下来仍然有效的两条老规矩：
>
> - **已确认和待核实必须用不同形状区分**，不能只靠颜色
> - **不做三维模型资产**——不建楼、不买 3D 城市模型、不引 3D Tiles。数据驱动的挤出渲染不在此列，几何来自公开数据 = 可以，几何来自人工建模或商业资产 = 不做

### 6.1 一句话

**照高德标准图做，暖白底、白路面、金黄主干道、极度克制的建筑。** 底图负责"这是哪"，我们自己的图层负责"发生了什么"。

具体色值、道路分级表、镜头参数和验收标准全部在 `视觉规格.md`。

### 6.2 技术选型

不换栈，继续 React + MapLibre + deck.gl。

Vue + Cesium 生态里现成的智慧城市大屏模板很多，但换栈等于把已经跑通的路由求解、离线底图回退、封路重算全部重写，四天半不够，而那三样恰恰是这个产品真正值钱的部分。

| 要做的 | 用什么 | 状态 |
|---|---|---|
| 高德风底图 | 自己写 MapLibre style JSON | 已装 |
| 建筑挤出 | MapLibre `fill-extrusion` | 已装 |
| 车流 / 出动单位 | deck.gl `TripsLayer` | 已装，没用起来 |
| 街道级车模、树 | deck.gl `ScenegraphLayer` + CC0 glTF | 已装，缺资产 |
| 3D 地球 | — | **不做**，跟叙事无关 |

**不能用高德底图本身**：高德是 GCJ-02 坐标系，OSM 是 WGS-84，混用会让我们所有数据（建筑轮廓、路网、医院 POI、5·16 那个地址）跟底图错位几百米到一公里。只能自己写 style 做视觉语言。

外部开源项目的用法见 `视觉规格.md` 附注：[streets-gl](https://github.com/StrandedKitty/streets-gl)（MIT，只抄观感不嵌代码，它的瓦片依赖自有服务器撞离线红线）、[three-cesium-examples](https://github.com/z2586300277/three-cesium-examples)（Apache-2.0，按需抄单个效果实现）。

### 6.3 图层清单

按从下到上的绘制顺序。**这张表是施工图。**

| 层 | 内容 | 实现 | 口径 |
|---|---|---|---|
| 0 | 陆地 / 水系 / 绿地 | style JSON fill | 公开 |
| 1 | 道路 casing | style JSON line，见视觉规格 2.2 | 公开 |
| 2 | 道路 fill | style JSON line，白 / 金黄 / 暗红分级 | 公开 |
| 3 | 建筑挤出 | `fill-extrusion`，估算层数用更浅的色 | 公开（52% 层数估算，须标） |
| 4 | 路况叠加 | 只叠主干道，**默认关闭** | **模拟** |
| 5 | 事发楼分层 | `fill-extrusion` 表达式，28 块楼板 | 起火层公开 / 烟气层推断 |
| 6 | 环境车流 | deck.gl `TripsLayer` | **模拟，须标** |
| 7 | 方案路线 | `PathLayer`，A 绿 / B 紫 / 120 青，带白描边 | **估算** |
| 8 | 出动单位 | `TripsLayer` + `ScenegraphLayer` | **模拟** |
| 9 | 路口开路 | `ScatterplotLayer` 脉冲 | **模拟** |
| 10 | 封路 | `PathLayer` 红虚线 | 用户输入 |
| 11 | 天气 | 全屏 Canvas 粒子 | **模拟** |

**第 6 层和第 8 层的区别是这次的胜负手**：环境车流是装饰，出动单位是方案。对标组只有前者。评委指着地图问"这车是什么"，我们能指到任务包里的具体一行。

## 7. 演示怎么走

### 7.1 现场脚本

1. 开屏页（炫）
2. 进态势总览 dashboard，让评委看城市全景和滚动告警
3. **当场手输**一条模拟数据（高层火情），点"开始研判"
4. 看系统补齐 → AI Brief → 两个方案 + 两份方案报告
5. 挑一个，批准
6. 任务包生成，送达到各负责人，状态流转
7. 制造一次异常 → 进资源调度面板手动改资源 → 重算 → 旧批准失效 → 重新批准 → 重试一次
8. 切到历史案例（荔湾 5·16）：公开事实 → CityOS 方案 → **街区级动态演示** → 复盘报告
9. 复盘报告沉淀进知识库

### 7.2 三条硬约束

1. **手输是我方操作，评委不输。** 输入内容必须落在预设模板范围内
2. **完整动态演示只做 2 个场景**：荔湾 5·16 火情、广州火车站持刀伤人（2015-03-06）。其他场景只出方案，不做车辆动画
3. **必须能离线跑**，断网不能灰屏

## 8. 数据真假边界

这是评分维度，界面上必须分得清。

| 真实（可标"公开数据"） | 模拟 / 估算（必须标） |
|---|---|
| 城市底图、路网 | 消防站能力、消防车数量 |
| 建筑轮廓、层数 | 消火栓、避难场所 |
| 医院、派出所 POI | 所有资源的实时状态 |
| 荔湾 5·16 的接警时刻、地址、扑灭时刻 | 事件流、Signal |
| 广州火车站 2015-03-06 的日期、时刻、地点、伤亡数 | 所有 ETA、路况、信号配时 |

**三态用形状区分**：实心=公开真实，空心=模拟，半填充=估算。

## 10. 大重构怎么做

这是这份文档最要紧的一节。**重构最常见的死法不是做不完，是做到一半两边都不能跑。** 交付日期是周二，任何一天醒来发现"现在这版演不了"都是灾难。

### 10.1 核心原则：平行重建，不原地改

**新代码全部建在 `src/v3/` 下，旧代码一行不动。**

```
src/
  engine/          ← 不动，直接复用
  agent/           ← 不动
  lib/             ← 新建：从旧代码抽出来的可复用底层（见 10.2）
  v3/              ← 新建，全新 UI，高德风浅色
    entry/         进入页
    dashboard/     态势总览
    incident/      事件处置
    resources/     资源调度
    knowledge/     知识库（浅色）
    map/           地图图层系统
    report/        两份报告（浅色）
    tokens.css     深浅两套 token
  components/      ← 旧的，暂时不动
  App.tsx          ← 只加一处路由分叉
```

`App.tsx` 里加一个开关：`#/v3` 走新的，其他走旧的。**做完最后一天再把默认翻过来。**

这么做换来三件事：

1. **任何时刻都有一个能演的版本。** 新的没做完之前，旧的还在
2. **Cursor 只建新文件**，不碰 `App.tsx`、`CityMap.tsx` 这些热点，多个批次不会打架
3. **随时能对比**，新旧并排开两个标签页

代价是最后要清理一次旧代码。这个代价值得付。

### 10.2 留什么、扔什么

**必须留（重写代价高，且和 UI 无关）**

| 东西 | 在哪 | 为什么留 |
|---|---|---|
| 推演引擎 | `src/engine/` | 纯函数，ETA 和覆盖计算 |
| 路径求解器 | `src/pages/routingViewModel.ts` 的 `solve()` | A/B 双图、封路重算、不可达降级，这是产品最值钱的部分 |
| 离线底图回退 | `CityMap.tsx` 里那段 | 8 秒超时切本地 PNG，是"断网不灰屏"红线的实现 |
| MapLibre worker 的 Vite 配置 | `vite.config.ts` | 线上灰屏的根因修复，踩过坑，别再踩一次 |
| 数据文件 | `public/data/*` | OSM 真实数据，重新拉一次要半天 |
| 浅色 token | `主看板定稿-规格.md` | 报告和知识库继续用 |

**第 2 到第 4 项要先抽到 `src/lib/`**，让新旧都能 import，不要复制粘贴两份。这是第一天第一件事。

**扔掉（方向错了，改不如重写）**

- `src/components/dashboard/` 下所有 UI 组件——九环结构、四个 tab、浅色布局
- `src/App.tsx` 的三栏/双栏布局
- `ScenarioMap.tsx` 那四张假场景图（它们是"四个雷霆例子当导航"的产物，结构就是错的）

**注意别误伤**：`FloorStatusPanel.tsx` 和那套 28 层楼板的挤出配置**要留**，那是我们相对对标组的差异点，只需把配色换成浅底。
