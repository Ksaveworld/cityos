## 核心决策：不做数字孪生，分两个尺度

### 为什么不做数字孪生

三条依据，任何一条单独都够：

1. **比赛官网第一句话就是「不是再造一块城市大屏」。**做一个三维城市，恰好撞在评委最想避开的刻板印象上。
2. **中国城市拿不到公开的 3D Tiles 数据。**Cesium 那套标准方案没有数据来源，做不了。
3. **侨银的 CityPilot 全程没有地图**，是对话式工作台。我们的对标物本身就没走这条路。

### 但高层火情确实需要高度维度

12 楼着火、避难层在 16 楼、被困人员在 20 楼——这个信息二维平面地图表达不了。

**解法是两个尺度分开做：**

| 尺度 | 做法 | 成本 |
|---|---|---|
| **城市** | MapLibre `fill-extrusion` + deck.gl 图层 | 几行配置 |
| **建筑** | 原生 SVG 楼层剖面 | 零依赖，32 个 `<rect>` |

**这个组合的视觉冲击力和信息密度，都超过一个做得粗糙的三维城市，成本差一个数量级。**

## 城市尺度

### 视觉参考

deck.gl 官方的 **TripsLayer 示例**（`https://deck.gl/images/examples/trips-layer.jpg`）就是目标效果：深色底图 + 挤出的建筑体块 + 发光的车辆轨迹动画。

**这是第一个要做出来的效果。**做出来之后整个 demo 的视觉基调就定了，后面所有页面照这个标准走。

### 图层映射

| deck.gl 图层 | 我们用来做什么 | 优先级 |
|---|---|---|
| **TripsLayer** | 消防车出动路径动画，从消防站到事发楼栋 | **P0** |
| **MapLibre `fill-extrusion`** | 建筑体块，着火楼栋标红 | **P0** |
| ScatterplotLayer | 资源点位：消防站、医院、警力 | P0 |
| **PolygonLayer（挤出）/ GeoJsonLayer** | **覆盖缺口、风险分区**，按数值上色 | P1 |
| ArcLayer | 调度关系连线：消防站 → 事发地 | P1 |
| TerrainLayer | 地形起伏。深圳有梧桐山、莲花山，加上去立体感提一档 | P2，加分项 |
| HeatmapLayer | 人流 / 警情密度 | P2 |

### 建筑挤出的配置

数据就是 OSM 建筑轮廓 + `building:levels`（深圳福田罗湖实测覆盖率 48.2%，见 `数据边界.md`）：

```js
map.addLayer({
  id: 'buildings-3d',
  type: 'fill-extrusion',
  source: 'buildings',
  paint: {
    'fill-extrusion-height': ['*', ['get', 'levels'], 3],   // 层数 × 3 米
    'fill-extrusion-color': ['case',
      ['==', ['get', 'id'], ['literal', eventBuildingId]], '#ff5f4d',
      '#2a3240'
    ],
    'fill-extrusion-opacity': 0.88
  }
})
```

层数缺失的建筑给默认值（住宅 6 层、商业 3 层），**并在图例里标注为估算**。

## 建筑尺度：SVG 楼层剖面

### 它要证明什么

不是"好看"，是**把接口契约里的 `confidence` 字段变成看得见的东西**。

评委看这一屏，应该立刻得到三个判断：

1. 这个系统知道自己哪些信息是可靠的
2. 它没有把不确定的东西说得像确定的
3. 它在几十秒内把散在多条报警里的信息拼成了一个可判断的整体

**这三条正好命中「真实与诚信」和「产品判断」两个评分维度。**

### 视觉编码规则（重要）

**已确认和待核实必须用不同的形状编码，不能只靠颜色。**色盲用户、黑白打印、投影偏色，都要还能分辨。

| 状态 | 填充 | 描边 |
|---|---|---|
| `confirmed` 已确认 | 实心，语义色 | 无 |
| `inferred` 推断 | 实心，语义色 | 无 |
| `reported` 仅报告 | **不填充** | **虚线，`#e3c14e`** |

### 语义色板

```
--fire:       #ff5f4d    起火层（已确认）
--smoke:      #e8964a    烟气蔓延（推断）
--refuge:     #3fb98a    避难层 / 安全
--unverified: #e3c14e    待核实（配虚线描边）
--cool:       #4d8fd6    资源 / 中性动作
```

### 中性色（深色主题）

```
--bg:      #12161d
--panel:   #1a202a
--panel-2: #212936
--line:    #2c3644
--ink:     #e7ecf3
--ink-2:   #93a0b3
--ink-3:   #66748a
```

**深色是刻意的单一主题选择**，不是省事——指挥席本身就是深色环境。不做浅色版。

### 字体

不引 webfont（中文字体体积太大，且外网加载有风险）。

```css
--mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;
--sans: system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

楼层号、时间、数值一律用等宽 + `font-variant-numeric: tabular-nums`。

## 明确不做

| 不做 | 原因 |
|---|---|
| CesiumJS + 3D Tiles | 中国城市拿不到公开 3D 数据 |
| Unreal / Unity | 17 天不可能，且正是"上一代数字孪生"的做法 |
| Three.js 手写三维 | deck.gl 底层就是 WebGL，重复劳动 |
| 真实 3D 建筑模型 | 没有数据源 |
| 浅色主题 | 指挥席场景不需要 |

**整套方案没有一处需要真正的 3D 建模。**全部是「数据 + 配置 → 渲染」，这恰好是 AI 最擅长的区间。
