## 首页

原来是两张扁平卡（日常响应 / 5·16 公开复盘）加一张主色卡，三个平权入口。进来第一件事是做选择题，而这三个选项对第一次看的人没有区分度。

现在整屏单列居中：口径 chip、标题、一句话、一颗主 CTA，底下一行纯文字写清进去有什么（态势总览 · 事件处置 · 资源调度 · 沉淀知识库）。**那一行不是按钮**——做成可点的卡片就又变回多入口了。

两条支线都没丢，往里挪了一层：日常响应是事件处置台账里的金融城高层火情，5·16 在同一页的历史事件栏。

## 城市告警流

原来每条告警占两行标题加一行来源，十几条堆在 264px 宽的侧栏里，满屏都是字。字多不等于信息多：真正要读的三件事是「哪个域在响、响得密不密、有没有警示级」，文字流一件都答不快。

改成时序点阵：一条告警是一个点，横轴是先后，纵轴是业务域（119 / 110 / 120 / 交通 / 布防 / 气象）。严重级用**大小加填充**编码，不只靠颜色——实心大是警示、实心中是关注、空心小是提示。下面一行分级计数，最底下只留最新一条的一行文字。

气象单独一条道：它是全城性的，没有地图落点，不该混进五个业务域里。

## 事件处置右栏

拆成今日事件和历史事件，理由不是排版是**时间口径**：今日台账回答「现在要处置什么」，历史案例回答「这套东西在已经发生过的事情上跑出来是什么样」。

广州站 2015 那条原来混在今日台账里、时间列写着「历史」——读的人分不清它是今天的活儿还是复盘材料。移进历史事件后今日台账从 23 条变 22 条。

今日那块做成可折叠，否则历史事件永远压在滚动条下面。

历史事件三条按线框图：

| 案例 | 入口 |
|---|---|
| 荔湾 5·16 服装交易市场火灾 | 进公开复盘推演（liwan-fire + public-review） |
| 广州火车站持刀伤人（2015） | 进站区案例推演（haizhu-police） |
| 台风山竹（2018） | **未建模**，只到知识库 |

台风山竹没有建模，也不打算为了凑满三条编一套出来：城市级气象灾害的资源调度模型和单点事件不是一回事，硬套就是造假。知识库里那条明确写「未建模」，卡上的按钮写「未建模 · 在知识库查看」，不给一颗点了没东西的「进入处置」。

每张卡的公开事实边界写在卡面上，不藏进详情——这是「真实与诚信」那一维最容易被抓的地方。

## 底部统计条

8/20 那轮已经从总览和资源调度撤掉，这轮事件处置也不要。剩下知识库一处不值得单留一个组件，`StatBar.tsx` 直接删除。数字都在侧栏五域态势里。

## 处置环节

定为六段：研判输入（Signal → Event → Context）、AI Brief、方案生成、任务下发、反馈、报告。

九个 chain key 一个没动。前三环本来就在侧栏折成「研判输入」一组，人工拍板本来就并在方案生成那一页（那页有人工批准按钮），改的只是上屏文案。

## 方案生成

见 `0cac691` 与 `6f73c62`。两件事：

- **受控调度**从「资源数量 + 资源点 + 负责人」三个抽象槽位，改成三个调度维度。原来的槽位拖动能让 ETA 变，但看不出这一步在协调哪几个部门，而跨部门协同正是这一步要给人看的东西。
- **「对比完整方案 A / B」按钮撤掉**。A/B 两张卡就在同一屏，ETA 与覆盖风险已经并排列出，再开浮层是同一件事的第二条链路。

第一版把三档做成按场景变名（交通场景成了「路况协同 / 医疗调度 / 交警开路」），被驳回。受控调度问的是「这起事件要调动哪几支力量」，答案在任何场景下都是同样三支，只是各自怎么配不一样；名字跟着场景飘，五个场景就没法横向比。

现在**三档固定出现、固定顺序**：消防调度 → 医疗调度 → 路况协同。选项按场景写，档名不动。数量滑杆挂在本域主责那一档下：

| 场景 | 滑杆挂在 | 滑杆内容 |
|---|---|---|
| 119 消防 | 消防调度 | 消防车辆 2–8 辆 |
| 120 医疗 | 医疗调度 | 救护车 1–4 辆 |
| 交通协同 | 路况协同 | 清障单元 1–5 组 |
| 110 警情 | 单列「警力调度」 | 模拟响应单元 2–6 组 |
| 重大布防 | 单列「布防调度」 | 保障岗位 4–16 个 |

110 与重大布防的主责不在这三类里，宁可多一档，也不把警力硬塞进「消防调度」那个框。

**A/B 方案对比本身保留。**「比较多个方案的后果」是 `CLAUDE.md` 里定的第五个闭环，是对标侨银四类闭环的唯一差异点，撤掉等于把差异化拿掉。8/21 与产品确认过：撤的是那颗重复按钮，不是对比本身。
