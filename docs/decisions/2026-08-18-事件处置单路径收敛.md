## A 组：现在做

四项都是实现缺陷，不依赖任何未定的设计方案，改完不会因为王君梅的方案返工。

### A1 合并态的环计数与 CTA 文案

会上点名的不匹配。做最小修复，不预设最终形态。

- `RightPanel` 头部的 `当前环 · {activeStep+1}/9`，在前四环收起时改成 `事件研判 · 1–4 / 9`；展开后回到具体环号。
- 底部 CTA 在合并态改成「进入方案推演」并直接 `setActiveStep(4)`，不再是「查看下一环」。展开态和 5–9 环保持现有文案与行为。

不动轨道的折叠逻辑，不动布局。

### A2 建议报告的回看链接落点

`RightPanel` 里包一层中转，同时传给 `ChainRail` 和 `LiwanStepPanel` 的 `onGoToStep`：

```ts
const goToStep = (step: number) => {
  if (step <= 3) setFoundationExpanded(true)
  onStepChange(step)
}
```

建议报告里「事件事实」和「上下文补齐」两节的回看是 `onGoToStep(1)` 和 `onGoToStep(2)`。不做这层中转就会落在合并摘要上，报告可追溯性静默退化。展开状态需要从 `ChainRail` 上移到 `RightPanel`，`activeStep === 4` 时自动收起的 effect 一起搬。

### A3 封路撤销人工确认时给出可见提示

`applyClosedWays` 里有 `setApprovedPlanId(null)`，而 `onCloseWay` 在任何环都是通的。用户走到任务环之后再封路，人工确认会被静默撤销，底栏「人工门禁」卡只会变回「待确认」，不说原因。

在底栏「人工门禁」卡的 note 位加一条条件文案：确认被封路撤销时显示「封路条件变更，需重新确认」，否则维持现有的「不会向任何真实部门自动下发」。

底栏四卡本轮保留，不删。

### A4 119 图标

`StatBar.tsx` 里 119 消防和 110 公安都用 `ShieldCheck`。119 换 `Flame`，110 保留 `ShieldCheck`，无人机的 `Plane` 不动。只有这两行。会上说这条无需优先处理，放最后一个提交，可跳过。

### C 组的硬边界

这几条来自 CLAUDE.md 和 `docs/数据边界.md`，升级成模拟展示之后更要守住：

- 代码和文案里**不得出现**「识别火焰」「检测火情」「视频分析」及同义表述。我们不做感知层，事件从上游已确认的接报进来。
- 三项信号必须带明确的模拟标识，说明未接入真实源。`OriginMark` 的形状编码照旧用，不能只靠颜色。
- 119 语音和火势多模态如果做，必须呈现为**模拟输入样例**，不能表述成系统已具备的识别或分析能力。
- 高层火情是模拟事件，不得套用 5·16 的公开锚点，也不得让两个模式的数据互相串。
