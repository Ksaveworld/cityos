## 页面结构

态势总览从「顶栏 / 左栏 + 地图 + 右栏 / 底部统计条」四块，改成三块：

```
顶栏
城市运行 · 实时（整条通栏，四张放大指标卡）
左栏读数 + 整幅地图
```

- **城市运行 · 实时**提到页面顶端。它原来挤在 264px 侧栏顶部，四个数字和下面的告警流、五域态势抢同一列宽度，读起来像侧栏的一个小节而不是全城口径。
- **右侧今日事件台账撤掉**。台账是事件处置的东西，总览负责「城市在跑什么」。中间地图不再被两侧夹成窄条。
- **底部六张统计条撤掉**，见下一节。

## 五域态势与底部统计条的重复

底部六张卡（119 消防 / 110 公安 / 120 急救 / 交警开路 / 无人机 / 水源）和侧栏五域态势是同一批数字：119 的「进行中 3」就是消防在办 3，110 的「待处置 8」就是警情在办 8，上下各写一遍。

处理：资源读数并进五域态势每一行右侧，无人机与水源不归属单一业务域，单独两行放在同一张卡里。底部整条撤掉。

规则定为**有侧栏的页面不再出现底部统计条**——总览和资源调度都有侧栏，事件处置和知识库没有，底部那条仍是它们唯一的出处。

侧栏一行放不下资源全称（264px 宽，缩到「站点 14 · 车 46」才不截断），缩写上屏、全称进 `title`。

**放弃的做法**：五域态势本来想做成每域两行，在办一行、资源一行。750px 高度下侧栏的告警流会被压到只剩一条，城市「活着」这个感觉就没了。

## 触发链路

原来从总览进处置有六条路：指标卡、五域态势行、告警流普通条、告警流主线条的红色「进入处置」按钮、地图落点、右侧今日事件卡。其中一部分直接跳进九环，一部分只是选中，落点不一致。

收敛成一条：**总览里所有事件类点击都落到事件处置的今日事件台账，并选中对应那条**，真正进九环在那边点。

| 入口 | 收敛后行为 |
|---|---|
| 顶部指标卡「今日事件 / 待人工决策 / 执行异常」 | 事件处置台账，带对应筛选 |
| 顶部指标卡「在途单位」 | 资源调度（它是资源口径，不是事件） |
| 五域态势 | 纯读数，不可点 |
| 城市告警流（含主线异常） | 事件处置台账并选中该事件 |
| 地图告警落点 | 同上 |

主线异常那条原来是一颗整宽红色按钮，和顶部指标条抢「这里点我」，改成一行文字链「在事件处置中打开」。

## 异常跳入

红色「新异常」横幅从总览的地图上挪到事件处置的今日事件分布上。总览负责看城市，跳进某一起事件的处置是事件处置的事。

## 已知限制

`docs/验收清单.md` 里「主看板能看到当前所有进行中的事件」「点任意事件能下钻到详情」两条，现在由事件处置承担；总览只给空间分布和计数。清单文案待与产品对齐后再改，不在本轮动。

## 数据边界

顶部指标条、五域态势、无人机与水源读数全部是模拟快照，各自带 `OriginMark origin="simulated"`。撤掉底部统计条时它那条整段口径声明一并撤掉，声明改挂在五域态势卡头部——标注不能因为搬家丢掉，见 `CLAUDE.md` 数据边界。
